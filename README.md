# Unrite Discord Bot

Discord-бот на Python `discord.py` для приватных архивов игроков, веток, ролей рангов и тиров. Название и подписи в интерфейсе используют **Unrite**.

## Возможности

- `/archi` или кнопка **Создать личный канал** создаёт один личный архив на участника.
- Канал скрыт от `@everyone`. По умолчанию его видят создатель и администраторы Discord; роли с назначенными управляющими разрешениями также получают доступ.
- Внутри канала создаются четыре приватные ветки: **РП мероприятия**, **Arena**, **Capt**, **MCL**.
- Если участник упоминает другого участника в личном архиве или одной из его веток, бот открывает упомянутому доступ к родительскому каналу и добавляет его во все четыре ветки.
- В панели архива есть два выпадающих меню в стиле скриншотов: **Взаимодействие с каналом** и **Выдача тира**.
- Управляющие действия: удалить канал, повысить ранг, понизить ранг, закрепиться, открепить куратора, выдать Тир 1/2/3.
- Роли тиров, рангов и куратора выбираются через slash-команды. Управляющие роли можно разрешать отдельно для каждой функции.
- На Railway настройки и список архивов хранятся в PostgreSQL; для локального запуска без `DATABASE_URL` используется SQLite.
- Есть `Dockerfile` и `docker-compose.yml` для запуска на сервере.

> **Имя канала:** Discord не использует пробелы и квадратные скобки в стандартных именах каналов. Поэтому канал называется в формате `архи-nickname` (например, `архи-kizaru-40684`), а исходный ник показывается в карточке профиля и в теме канала.

## 1. Создайте приложение Discord

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications) и создайте Application.
2. В разделе **Bot** добавьте бота и скопируйте токен. Не отправляйте токен посторонним и не выкладывайте его в репозиторий.
3. В разделе **Bot → Privileged Gateway Intents** включите **Server Members Intent** и **Message Content Intent**. Они нужны для выдачи доступа упомянутым участникам.
4. В разделе **OAuth2 → URL Generator** отметьте scopes `bot` и `applications.commands`.
5. Выдайте разрешения: `View Channels`, `Send Messages`, `Read Message History`, `Manage Channels`, `Manage Roles`, `Create Private Threads`, `Send Messages in Threads`, `Manage Threads`, `Embed Links`, `Attach Files`.
6. Пригласите бота на сервер. В списке ролей поднимите роль бота **выше всех ролей рангов, тиров и куратора**, которыми он должен управлять.

## 2. Установка на Windows

Установите Python 3.11 или 3.12, затем в папке проекта выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

В `.env` вставьте токен:

```env
DISCORD_TOKEN=ВАШ_ТОКЕН_БОТА
GUILD_ID=ID_ВАШЕГО_ТЕСТОВОГО_СЕРВЕРА
DATABASE_PATH=data/unrite.sqlite3
```

На локальном компьютере, если `DATABASE_URL` не задан, используется SQLite. Для подключения локального экземпляра к PostgreSQL задайте `DATABASE_URL` с адресом вашей базы.

`GUILD_ID` можно оставить пустым. Для разработки лучше вписать ID сервера: slash-команды появятся быстрее. ID включается в Discord через **Настройки → Расширенные → Режим разработчика**, затем правый клик по серверу → **Копировать ID**.

Запуск:

```powershell
python main.py
```

Или запустите `run.bat` после заполнения `.env`.

## 3. Первоначальная настройка в Discord

Выполните команды от имени владельца сервера, администратора или участника с `Manage Server`:

1. `/unrite setup category` — выберите категорию, внутри которой будут создаваться архивы.
2. `/unrite panel channel` — опубликуйте панель с кнопкой создания архива в нужном текстовом канале. Создать архив также можно командой `/archi`.
3. `/unrite tier_role tier role` — отдельно назначьте роль для **Тира 1**, **Тира 2** и **Тира 3**.
4. `/unrite rank_role position role` — настройте позиции рангов. Например, позиция `1` — начальный ранг, `2` — следующий, `3` — ещё выше. При повышении бот назначает следующую настроенную позицию; при понижении — предыдущую.
5. `/unrite curator_role role` — выберите роль, которую будет добавлять действие **Закрепиться** и убирать действие **Открепить куратора**.
6. `/unrite permission role function allowed` — выдайте определённой роли доступ к конкретной функции. Повторите для каждой функции, которая ей разрешена.
7. `/unrite status` — проверьте сохранённые настройки.
8. Если существующий архив потерял запись в базе, используйте `/unrite repair_archive` внутри этого архива.

### Доступ по управляющим ролям

В `/unrite permission` можно разрешать по отдельности:

- Удаление канала
- Повышение ранга
- Понижение ранга
- Закрепиться
- Открепить куратора
- Выдать Тир 1
- Выдать Тир 2
- Выдать Тир 3

Владелец сервера, администраторы и участники с `Manage Server` всегда имеют полный доступ к функциям управления. Остальные участники получают только те функции, которые разрешены их ролям. Когда роль получает хотя бы одно право управления, она сможет видеть созданные архивы и их приватные ветки. Чтобы отключить это, выключите все функции для роли.


## 4. PostgreSQL на Railway (рекомендуемый вариант)

1. В Railway откройте проект и нажмите **+ New → Database → PostgreSQL**. Дождитесь, пока база перейдёт в состояние запущенной.
2. Откройте сервис **Unrite** → **Variables** → добавьте ссылочную переменную `DATABASE_URL`, выбрав `DATABASE_URL` у PostgreSQL-сервиса. Используйте внутреннюю ссылку Railway, а не публичную строку, если бот работает в том же Railway-проекте.
3. Убедитесь, что в сервисе Unrite есть `DISCORD_TOKEN` и при необходимости `GUILD_ID`. Не добавляйте вручную `DATABASE_PATH` как PostgreSQL-строку: `DATABASE_PATH` нужен только для локального SQLite.
4. Сделайте **Redeploy**. В логах запуска должна появиться строка `Database backend: PostgreSQL (...)`. Если вместо неё написано `SQLite`, переменная `DATABASE_URL` не передалась приложению.
5. После первого успешного подключения PostgreSQL таблицы создадутся автоматически. Если это новая пустая база, повторно настройте `/unrite setup category`, `/unrite panel channel`, роли тиров/рангов/куратора и разрешения управления.

**Важно о существующих настройках.** Новая PostgreSQL-база не получает данные из SQLite автоматически. Если нужно сохранить уже заданные роли, разрешения и записи архивов, сначала перенесите старый файл SQLite и выполните скрипт миграции ниже. Не удаляйте исходную SQLite-базу, пока не проверите результат. Если старый файл находился только в файловой системе Railway без подключённого постоянного тома, проверьте доступность резервной копии до повторного деплоя.

### Миграция SQLite → PostgreSQL

Скрипт `migrate_sqlite_to_postgres.py` копирует записи из пяти таблиц (`guild_settings`, `permissions`, `tier_roles`, `rank_roles`, `archives`) и не изменяет исходный SQLite-файл. Перед переносом остановите работающего бота или выполняйте миграцию до переключения его на PostgreSQL.

В PowerShell из папки проекта:

```powershell
python -m pip install -r requirements.txt
$env:DATABASE_URL = "ВАША_СТРОКА_ПОДКЛЮЧЕНИЯ_POSTGRESQL"
python .\migrate_sqlite_to_postgres.py --sqlite .\data\unrite.sqlite3
```

Указанный адрес должен быть доступен с компьютера, где запускается миграция. В Railway private `DATABASE_URL` обычно доступен только внутри сети Railway; для локального переноса используйте временный Railway TCP Proxy / public URL или запустите миграцию из окружения, имеющего внутренний доступ. Не оставляйте публичный доступ к БД включённым после миграции. Скрипт пропускает строки с конфликтующими ключами в целевой базе, поэтому для первого переноса предпочтительна пустая PostgreSQL-база.

### Переменные окружения Railway

В сервисе Unrite добавьте `DATABASE_URL` именно как reference variable, указывающую на PostgreSQL service. Если сервис базы называется `Postgres`, выражение будет `${{Postgres.DATABASE_URL}}`. Railway документирует этот способ подключения в [PostgreSQL Docs](https://docs.railway.com/databases/postgresql) и [Variables](https://docs.railway.com/variables).

## 5. Запуск через Docker

Скопируйте `.env.example` в `.env`, заполните `DISCORD_TOKEN` и выполните:

```bash
docker compose up -d --build
```

Локальная база будет храниться в `./data` и останется на месте после пересборки контейнера.

## Если появляется «Эта панель не привязана к архиву Unrite»

Эта ошибка означает, что в используемой базе данных нет записи для текущего канала — например, бот подключён к новой PostgreSQL-базе, но данные старой SQLite ещё не перенесены. В этом случае сначала попробуйте перенести SQLite-данные скриптом миграции выше. Если старых данных уже нет, команда восстановления может создать новую запись для существующего канала, но предыдущие значения ранга и тира автоматически не восстановятся.

Чтобы восстановить существующий архив без его удаления:

1. Обновите файлы проекта из исправленной версии и перезапустите бота.
2. Убедитесь, что архив находится в настроенной категории и что в теме канала есть `Unrite | Архив игрока: ... | ID: ...`.
3. Введите `/unrite repair_archive` прямо в проблемном архивном канале от имени администратора сервера. Можно также выбрать архив параметром `channel`.
4. Команда проверит категорию, ID владельца и все четыре ветки и восстановит привязку в базе. Она не удаляет архив.

Если команда сообщает, что ветки не найдены, проверьте право **Manage Threads** у бота и убедитесь, что в канале действительно существуют все ветки `РП мероприятия`, `Arena`, `Capt` и `MCL`. Не создавайте второй архив до восстановления привязки.

## Примечания и ограничения

- Discord ограничивает максимальное время автоскрытия неактивной ветки. Бот создаёт приватные ветки с максимальным доступным сроком и повторно открывает ветку при добавлении упомянутого участника.
- Участник, которому дали доступ упоминанием, остаётся в архиве, пока ему вручную не уберут доступ или не удалят архив.
- Для управления ролями роль бота должна быть выше целевых ролей. Роли, интеграции и права Discord могут блокировать выдачу даже при правильной настройке бота.
- Настройки доступа — серверные. Для тонкой настройки оставляйте администраторские права только доверенным ролям.
- Сначала протестируйте выдачу ролей и приватность на отдельном тестовом сервере.
